# SSDの取り外し(shiori-eject)

実機のSSDを安全に取り外せる状態にする機能。詩織本体を閉じても、MCPやRAGサーバー・埋め込みの`llama-server`などがSSD上で動き続け、取り外しを妨げることがある。この機能は、**実行ファイルのパスがSSD(`portable/`)配下にある、自分のユーザーのプロセス**を選んで、穏やかに止める。取り外し(Finderで取り出す操作)自体は行わない。

## 3つの入口(中核は共通: `src-tauri/src/eject.rs`)

| 入口 | 使い方 |
|---|---|
| CLI `shiori-eject` | 主にClaudeがBashから呼ぶ。`bin/mac/shiori-eject`(Windowsは`bin/win/shiori-eject.exe`) |
| 設定画面 | 設定ウィンドウの「SSDの取り外し」ページ。確認→「止めて詩織を終了する」 |
| 終了時の確認 | 詩織のウィンドウを閉じるとき、詩織を閉じても残るもの(MCPなどが起動した共有デーモン)があれば「関連するプロセスも停止しますか?」と聞く |

## CLI

```bash
shiori-eject            # 確認だけ。何も止めない
shiori-eject --yes      # 止める予定のものを停止する
shiori-eject --json     # 結果をJSONで出す(--yesと併用できる)
shiori-eject --root <portable/のパス>   # 省略時は実行ファイルの場所から探す
```

終了コード: 0=正常(使用中が残るだけでも0)、1=止められなかったプロセスがある、2=引数の誤り。

停止は、unixでは`SIGTERM`で穏やかに止め、最大10秒待って残るものを強制終了する。Windowsには穏やかな停止の手段がなく、強制終了になる。

## 止めないもの(使用中として報告する)

- **`mcp_server`**: Claudeのセッションが標準入出力でつないで使っている。外から止めると、そのセッションのMCP接続が復旧しない(library内の`decision-1790068500`)。親をたどった`claude`のプロセスとともに「使用中」と報告する。取り外す前に、そのセッションを閉じる(またはMCPを切る)。
- **SSDの外のプロセス**、**ほかのユーザーのプロセス**、**実行中の`shiori-eject`自身とその親**。
- **ほかのアプリがSSDのファイルを開いているもの**(エディタ、カレントディレクトリがSSDのターミナル等): Mac/Linuxでは`lsof`で見つけて報告するだけ。

## 取り外しの手順

1. `shiori-eject`で確認 → `shiori-eject --yes`で停止(または設定画面のボタン)。
2. 「使用中」に出たもの(Claudeのセッション)と、「ほかにSSDを開いているもの」を閉じる。
3. Finder(Windowsは「ハードウェアを安全に取り外す」)で取り出す。

## 制限

- `Cmd+Q`・Dockからの終了は、ウィンドウを閉じる操作ではないため、終了時の確認を通らない。
- Windowsでの動作は未確認(コードは共通)。
- 再度マウントしたあと、止められた共有デーモンは、最初に呼んだ側(詩織・MCP)が起動し直す。
