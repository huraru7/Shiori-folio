# 詩織 不具合対応記録

再発時に参照できるよう、原因が分かりにくかった不具合の対応内容を残す。

## whisper-server(STT)が日本語音声を英語として文字起こしする(2026-08-06)

**症状**: 日本語で話しかけたのに、文字起こし結果が英語の文章になっていた
(例: 「詩織のキャラクター名の由来って何だっけ」と話したのに
"What is the origin of the character name of Shiori?" と認識された)。
文法的に自然な英文だったため、単なる誤認識ではなく別の原因を疑う必要があった。

**原因**: whisper.cpp(`whisper-server.exe`)の`--language`オプションは、
デフォルトが`auto`ではなく**`en`固定**(`--help`で確認: `[en]`)。起動時に
明示指定していなかったため、常に「音声は英語のはず」という前提でデコード
されていた。日本語音声を英語として無理やり解釈しようとした結果、支離滅裂な
音の書き起こしではなく、それらしい(しかし内容は無関係な)英文が生成された
と考えられる。

**修正**: `src-tauri/src/lib.rs`の`SttManager::ensure_started`で、
whisper-server起動時の引数に`--language ja`を明示的に追加。

```rust
let args = [
    "--port", &port_str, "--host", "127.0.0.1",
    "--language", "ja",
    "--prompt", "詩織、ふらる、huraru.com、ポートフォリオ、lab.huraru.com",
    "--carry-initial-prompt",
];
```

あわせて、「詩織」が同音異義語(「仕寄り」等)に誤変換される問題への軽減策として、
`--prompt`(初期プロンプト)に固有名詞のヒントを追加。`--carry-initial-prompt`を
付けないと最初の1回のリクエストにしか初期プロンプトが効かないため必須。

**教訓**: サブプロセスCLIのデフォルト値は「常識的にautoだろう」と思い込まず、
`--help`で必ず確認する。今回のケースは、一見「自然な文章になっている」ことが
かえって原因調査を遅らせる要因になった(明らかに壊れた出力の方が異常だと
気づきやすい)。

## 詩織が自分自身を三人称で語る(2026-08-07)

**症状**: 「詩織の由来は?」等、詩織自身に関する質問に対し、
「詩織は『詩を織る』という意味で…」のように、まるで別人を紹介するような
三人称で回答してしまう。

**原因**: 常時軽量検索(自発的想起)で参考情報として差し込まれる
`library/profile/profile-huraru.md`の「詩織プロジェクトについて」
セクションが、当初三人称の解説文(「詩織は〜と設定されている」)で書かれていた。
LLMが直前に読んだ参考情報の文体をそのまま引きずってしまい、
プロンプト側の「一人称で話す」という指示より、直前の文脈の文体の影響の方が
強く出た。実際に発生時の会話ログを確認したところ、複数の応答が参考情報の
一文をほぼそのまま引用する形で三人称化しており、仮説を裏付けた。

**対応**:
1. `profile-huraru.md`の「詩織プロジェクトについて」セクションを全面的に
   一人称の文体に書き直し
2. 保険として、`send_message`内に後処理(`correct_third_person_self_reference`)
   を追加。「詩織は/が/も」を「私は/が/も」に機械的に置換する
   (「詩織の」等の名詞修飾パターンは、ユーザーが話題として「詩織」を
   使っているだけの場合との誤爆リスクが高いため対象外)

**未解決の課題(2026-08-07時点)**: 文書の一人称化・後処理の追加後も、
以下がまだ残っている。
- passive recall(常時軽量検索)が、詩織自身に関する一部の話題
  (使用LLM、将来の目標等)で安定してヒットしない
- 参考情報が見つからない場合、指示(「作り話をしない」)を追加したにも
  かかわらず、LLMがそれらしい創作をしてしまうことが多い
- 後処理は「詩織は/が/も」のみを対象にしているため、「しおりさんの」
  「詩織の」等、別の言い回しでの三人称化はすり抜ける

これらはプロンプトの指示だけでは制御しきれない、量子化モデル特有の限界と
考えられ、引き続き調整が必要。
